## Finding fixed during verification
The timestamp is **one running clock across all 106 recordings**: 105 of 105 consecutive recording boundaries are exactly one sampling step apart. Phase 1's gap check therefore could not see recording boundaries, and any window built from timestamp continuity would silently cross recordings. Phase 1 grouping by `recording_id` was already correct, so no data or rule was changed; a new warning `RECORDING_BOUNDARIES_INVISIBLE_IN_TIMESTAMPS` (in `quality.py`) now documents it, and Phase 2 windows are built strictly inside one `recording_id` (tested). Regression tests: `tests/test_phase1_regression.py`.
