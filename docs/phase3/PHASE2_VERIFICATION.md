## Checklist 4 - Phase 2 forecasting integrity
* **Reproduction.** `prepare_phase2_windows.py` and `evaluate_phase2.py` were re-run: the regenerated
  `phase2_results_report.md` is **byte-identical** to the supplied one; `phase2_metrics.json` differs only in the
  `build_seconds` timing field.
* **Target/leakage rules** (reviewed in `windows.py`, `events.py`, `prepare.py` and covered by Phase 2 tests): events come
  from annotations; the target is "an episode starts within the horizon"; windows use only samples up to the anchor;
  anchors with an ongoing episode or whose window overlaps one are excluded; futures that run past the recording end are
  censored; windows never cross recordings; evaluation is participant-grouped; thresholds come from inner participant-grouped
  predictions of the training participants only.
* **Artifact gate (critical).** 24 manifests, 24 `.joblib` files. For each: file exists, SHA-256 equals the manifest,
  `config_hash` equals the current `phase2.yaml` hash, and `ForecastPredictor.load` succeeds (this includes the saved
  preprocessing pipeline and feature schema). No manifest lacks its model file. Nothing was fabricated or retrained.
* **Inference parity (real data).** For 60 randomly sampled eligible real anchors x 3 models (180 predictions) the
  probability from `ForecastPredictor.predict` on the raw trailing window equals the saved pipeline applied to the cached
  training-time features: **maximum absolute difference 0.0**. A short window, a full-length window containing a 0.5 s timestamp
  gap, non-increasing timestamps (all `InferenceInputError`) and a window with one sensor position entirely NaN
  (`insufficient_sensor_quality`, no probability returned) were each refused. Latency 18-48 ms per prediction in that test;
  mean 19 ms / max 71 ms over the 922 forecasts of the full replay.
* **Finding (no action needed).** Training forward-fills over the whole recording while the predictor fills only inside the
  trailing window, so at a window's first samples inference is equal or *stricter* than training. It can only withhold a
  forecast, never admit extra data, so it is not a leakage risk.

## Model performance (carried forward, not hidden)
From the reproduced report, for the model Phase 3 uses by default (sensor-only random forest, 3 s horizon): event
sensitivity 0.21 (95 % CI 0.04-0.35; 16/75 evaluable events), 74 false alerts per hour (CI 24-124) although the threshold was
chosen for a 30/h budget, AP 0.134, ROC-AUC 0.704, Brier 0.109 versus 0.062 for the prevalence-only reference. Across models
and horizons sensitivity is low and variable, intervals are wide, and clinical fusion shows no consistent advantage over
sensor-only. **A technically functional model is not an effective forecaster.** Phase 3 therefore labels every output a
research score, never calls it a probability or a clinical warning, and the replay tooling states that results are in-sample.
